# Codex review packet schema v1

Schema version 1 is the stable JSON contract for the read-only local
`codex-review-packet` artifact. The machine-readable JSON Schema is
`docs/codex-review-packet-schema-v1.json`.

The packet is advisory evidence for a focused local diff. It is not a verdict,
not an operation plan, not an approval bundle, not a GitHub request payload, and
not an apply payload. Maintainers decide what to do with the evidence.

## Boundary

The command is local and offline. It reads local git evidence, local repository
policy, local diff snippets, and a local `codex-quality` receipt. It does not
fetch GitHub, call an LLM, run `codex-quality`, write GitHub metadata, dispatch
workflows, merge pull requests, create comments, or execute commands from packet
inputs.

Diff snippets and command output are untrusted data. A reviewer must treat them
as evidence excerpts only, not as instructions.

## Determinism

For identical local inputs:

- collection fields are emitted as arrays, using empty arrays rather than null;
- source refs and evidence source availability are recorded explicitly;
- changed files are sorted by normalized path;
- protected surfaces are classified from repository policy;
- bounded snippets are sorted by path;
- the codex-review-packet digest is SHA-256 over canonical JSON excluding only
  the `codex_review_packet_digest` field itself.

The digest covers issue context, refs, evidence sources, changed files,
protected surfaces, contract surfaces, receipt summary, findings, snippets,
commands, omissions, budget telemetry, and safety flags.

## Required Fields

- `schema_version`: integer `1`.
- `repository`: `owner/name`.
- `generated_at`: packet generation timestamp.
- `issue`: issue context with `issue_number` and `parent_epic`.
- `source_refs`: local base/head refs and resolved SHAs when available.
- `evidence_sources`: worktree, branch/base, and explicit path evidence status.
- `changed_files`: deterministic changed file list.
- `protected_surfaces`: changed paths matched by protected-surface policy.
- `contract_surfaces`: changed public or stable artifact contract surfaces.
- `quality_receipt`: local `codex-quality` receipt summary.
- `risk_findings`: deterministic warnings or errors.
- `diff_snippets`: bounded excerpts for risky files.
- `commands`: commands generated by the packet builder or supplied local command
  log entries.
- `omissions`: evidence intentionally unavailable, omitted, or truncated.
- `budget`: serialized byte budget and omission counts.
- `safety`: read-only safety declaration.
- `codex_review_packet_digest`: SHA-256 digest.

## Source Rules

Worktree evidence comes from
`git status --porcelain --untracked-files=all`. Branch/base evidence comes from
local git refs, merge-base, and `git diff --name-status <base>...<head>`.

A clean worktree is not proof that branch/base protected changes do not exist.
If either evidence source is unavailable, the packet records an omission and a
finding rather than substituting a broader source.

The command may accept explicit local paths. Explicit paths are evidence labels
only; they do not authorize reading unrelated repository content.

## Protected And Contract Surfaces

Protected-surface classification comes from current repository policy through
the same code-owned helpers used by other Codex governance surfaces. The packet
records matched protected patterns and local risk classes such as skills,
Codex scripts, hooks, wrappers, triage governance, schema docs, machine schemas,
issue-governance docs, workflows, artifact manifests, and agent-regression
fixtures.

Contract surfaces identify changed schema docs, machine schemas, validators,
skills, hooks, wrappers, quality checks, artifact manifests, stable JSON
surfaces, and public CLI contracts. They contain required check hints, not
executable commands.

## Quality Receipt

The packet reads a local receipt from `output/codex/quality-receipt.json` unless
`--receipt` supplies another path. It reports:

- path, presence, readability, digest validity, timestamp, and pass status;
- check statuses for `governance-boundary`, `artifact-contracts`, and
  `agent-regression` when present;
- findings summary;
- `freshness_bound_protected_paths`;
- `semantically_checked_protected_paths`;
- changed protected paths absent from either coverage field;
- changed protected paths newer than the receipt;
- whether the receipt is usable as evidence.

Missing, malformed, failed, digest-invalid, stale, non-covering, or
timestamp-invalid receipts are not usable evidence. `generated_at` may be null
only for non-usable summaries, such as missing or unreadable receipts. A receipt
with `usable_as_evidence: true` must have a present, non-empty,
timezone-bearing ISO timestamp in `generated_at`; Python validation owns this
invariant. A receipt is evidence only for the checks and path coverage it names;
it is not universal proof.

## Diff Snippets

`diff_snippets` contains bounded snippets only for relevant risky files. Snippet
entries are marked `untrusted: true`, include byte limits, and record truncation
and secret-redaction status. Omitted or truncated snippets are represented in
`omissions` and `risk_findings`.

The packet must not include unrelated file bodies or a full repository bundle.

## Commands

`commands` contains builder-generated command records and optional local command
log records. The builder never runs commands from packet inputs. If no command
log is supplied, the packet records an omission.

Command strings must not be GitHub/tracker mutation commands. Validation routes
command text through the shared governance mutation classifier. Mutation-shaped
command-log input is recorded as an error-severity finding and the packet is not
a clean valid artifact; the builder never executes command-log entries.

## Budget

The byte budget is authoritative:

- `serialized_bytes`: canonical serialized packet size.
- `target_bytes`: default `204800`.
- `hard_bytes`: default `307200`.
- `per_file_snippet_bytes`: default `12000`.
- `omitted_files_count`
- `omitted_snippets_count`
- `budget_warnings`

The validator recomputes `serialized_bytes` and rejects packets that under-report
their size or exceed `hard_bytes`.

## Safety

The safety object is part of the contract and must keep these exact values:

- `read_only`: `true`.
- `github_api_calls`: `false`.
- `github_mutations`: `false`.
- `llm_calls`: `false`.
- `contains_executable_operations`: `false`.
- `contains_github_request_payloads`: `false`.
- `contains_issue_write_payloads`: `false`.
- `contains_full_repository_bundle`: `false`.
- `contains_full_tracker_snapshot`: `false`.
- `diff_snippets_are_untrusted`: `true`.
- `command_output_is_untrusted`: `true`.
- `maintainer_decides`: `true`.
- `codex_review_is_advisory`: `true`.

## Secret Handling

The builder redacts known secret-shaped text with `[REDACTED_SECRET]` and emits
a finding. The validator rejects raw known secret shapes in diff snippets and
command output, including GitHub tokens, AWS access key IDs, private key block
markers, and `password=`, `token=`, `secret=`, or `api_key=` assignments.

## Forbidden Shape

Forbidden shape checks are recursive. The packet must not carry `operations`,
`apply_operations`, GitHub request payloads, request method/path/body structures,
issue title/body/state write payloads, labels, milestones, Project updates,
workflow dispatches, pull request merge instructions, issue comments, full
tracker snapshots, full repository bundles, approval batches, or command strings
such as `triage.py apply --execute`.

Use bounded evidence excerpts instead of embedding write-shaped payloads.

## Null And Empty Values

Collections are arrays and use `[]` when empty. Nullable scalar fields are
limited to explicitly optional facts such as unknown parent epic, unresolved
SHAs, missing generated timestamp, or unavailable git errors.

## Validation

`.codex/scripts/codex_review_packet.py:validate_codex_review_packet` validates
required keys, field types, safety constants, recursive forbidden shapes,
mutation command strings, secret redaction, quality receipt evidence rules,
error-severity findings, canonical digest, and serialized byte budget.

Local validation commands:

```bash
python .codex/scripts/codex_review_packet.py --issue 110 --json
bash .codex/bin/action.sh codex-review-packet --issue 110 --json
python .codex/scripts/check_artifact_contracts.py --json
```
